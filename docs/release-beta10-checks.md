# Nova beta.10 — локализация и нагрузка 50 пользователей

Проверено 22 октября 2026 года на Windows, Intel Core i3-13100F (8 логических процессоров).

## Изменения производительности

- Проверка сессии и чтение существующего профиля объединены в один подготовленный SQL-запрос. Права, блокировка аккаунта и срок сессии читаются из базы на каждом обращении: устаревшего кеша авторизации нет. Создание отсутствующего профиля сохранено.
- Повторяющиеся запросы настроек используют кеш подготовленных выражений; общий лимит — 64 выражения. Результаты настроек не кешируются.
- Проверка и создание паролей ограничены двумя параллельными Argon2-операциями. Очередь асинхронная; отмена HTTP-запроса не освобождает слот раньше завершения вычисления. Обычный хеш требует около 19 МиБ, поэтому пик рабочей памяти хеширования ограничен примерно 38 МиБ, без учёта прочей памяти процесса. Защита паролей не ослаблена.
- В release встроенные файлы интерфейса передаются без дополнительного копирования всего файла в отдельный Vec для каждого запроса. ETag позволяет отвечать 304 при совпадении версии; изменённые файлы возвращаются полностью.
- Обновления значков не перекрываются; небольшой случайный интервал уменьшает синхронные всплески опроса. Переписки не запускают второй опрос до окончания первого и отменяют запрос при закрытии компонента.
- Аналогичное ограничение Argon2 добавлено в Java preview; при закрытии локализатора закрывается HTTP-клиент.
- Устранены гонки запуска ffmpeg при одновременном запросе одного HLS-фрагмента и одной копии видео: проверка существующей задачи и регистрация новой синхронизированы. Уже завершённая копия повторно используется.

## Нагрузочная проверка

`server/tests/party.rs::fifty_active_viewers_receive_controls_and_query_without_errors`:

- 50 отдельных аккаунтов и публичных HTTP-сессий, 50 открытых SSE-подключений одной комнаты.
- 1000 запросов `/api/badges` (по 20 на пользователя), без ошибок: p50 9,37 мс; p95 39,94 мс; максимум 60,64 мс.
- 400 авторизованных Range-запросов по 256 КиБ — суммарно 100 МиБ. Проверены статус 206, Content-Range, длина и содержимое ответа.
- 20 последовательных и 50 одновременно отправленных команд комнаты. Все 50 подписчиков получают одинаковый порядок ревизий и положение просмотра. Повторный вход сохраняет последнее состояние.
- После блокировки пользователя следующий запрос с его старой сессией возвращает 401.

API и Range-фаза заняли суммарно 0,92 с; настройка аккаунтов/паролей в этот интервал не входит. Это короткий локальный синтетический прогон debug-сервера, а не длительный тест 50 физических видеоплееров или облачного туннеля. Файл Range-проверки синтетический; декодирование и 50 независимых перекодирований не проверялись. Процент снижения CPU и памяти относительно старой версии не измерялся.

Для 50 потоков по 5 Мбит/с через хост требуется минимум 250 Мбит/с исходящего канала плюс запас. Если видео загружается напрямую с внешнего источника, канал хоста расходуется иначе. Ограничители тяжёлого перекодирования сохранены: 50 отдельных ffmpeg-процессов автоматически не запускаются.

### Уточнённая цель: 50 одновременно смотрящих зрителей

Пользователь подтвердил исходящую скорость 500 Мбит/с или выше. Выполнен дополнительный прогон `NOVA_STREAM_LOAD_SECS=60` с 50 отдельными синтетическими файлами и 50 публичными сессиями: каждый клиент запрашивает 256 КиБ раз в 250 мс по фиксированному расписанию. Проверяется всё содержимое ответа сравнением буферов. SSE, 1000 запросов интерфейса и команды комнаты выполняются на фоне передачи.

Результат (`logs/performance-50-fixed-rate.log`):

- 12 000 Range-ответов, 3000 МиБ за 59,81 с, **420,8 Мбит/с суммарно**, около 8,4 Мбит/с на клиента.
- Ошибок статуса, длины, содержимого и порядка команд нет.
- API: p50 6,45 мс, p95 12,00 мс, максимум 48,10 мс.
- Полная загрузка Range-ответа: p95 55,86 мс, максимум 613,17 мс. Буферизация видеоплеера остаётся необходимой: не каждый отдельный запрос быстрее 250 мс.

Генератор использует `MissedTickBehavior::Burst`: опоздавшие таймеры догоняют фиксированное расписание, сохраняя заданную среднюю нагрузку. Предыдущие прогоны с `Delay` сдвигали последующие запросы после опоздания и фактически подавали меньшую нагрузку: 352,6 и 314,7 Мбит/с; эти журналы сохранены. Это изменение методики нагрузки, а не дополнительное ускорение продукта между прогонами.

Генератор и debug-сервер работают на одном компьютере через loopback; файлы малы и помещаются в дисковый кеш. Не проверены 50 устройств с декодированием, 50 различных фильмов с диска большого объёма, внешние CDN и фактическая пропускная способность CloudPub. Данный результат подтверждает локальный путь авторизации/Range-раздачи и синхронизации при заданной нагрузке, а не безусловную гарантию любого качества через интернет.

- Clippy всего workspace и всех targets с `-D warnings` — пройдено. `logs/performance-clippy.log`.
- Отдельная проверка `netflix`: 50 одновременно запрошенных холодных HLS-фрагментов возвращают одинаковые данные, 50 запросов копии получают плейлист; реальный ffmpeg-клиент декодирует HLS. Пройдена за 3,20 с (`logs/performance-media.log`). Это общий поток одного видео, не 50 независимых перекодирований.
- Svelte: 0 ошибок и предупреждений; production-сборка завершена.
- Vitest: 17 проверок в 7 файлах — пройдены.
- Java preview: сборка и проверки совместимости Argon2, сессий, миграций, локализации и модели комнаты с 50 подписчиками/50 одновременными командами пройдены. Полные HTTP-видеопотоки Java пока не реализованы.

- Release EXE сообщает `1.0.0-beta.10`; байты актуальных JS-модулей плеера и фоновых значков обнаружены внутри EXE. Финальная сборка после исправления гонок ffmpeg: `desktop/beta10-performance-build.log`.

## Локализация серий

Названия и описания старых кешированных сезонов проходят через отдельный русский кеш. При отсутствии перевода название отображается как «Серия», английское описание скрывается; оригинальные данные сохраняются. Исправлены также подписи текущей и следующей серии в плеере. Явный режим исходного языка сохранён.

До оптимизаций пройдены 8 проверок страницы серий на телефоне, планшете, компьютере и WebKit; 5 проверок плеера/HLS/совместного просмотра, включая 10 отдельных декодирующих браузерных плееров. Сервис перевода вернул русский текст для трёх названий из примера. Перевод машинный, зависит от доступности сервиса; официальные русские названия всех серий не гарантируются.

## Состояние Java

Полный перенос сервера **не завершён**. Основной установщик использует Rust. Самостоятельный `server-java` реализует 10 из 137 маршрутов и ещё 2 частично; неперенесённые API явно возвращают 501. Java не проксирует Rust. Подробности и команды запуска — в `server-java/README.md` и `api-migration.csv`.
