# Автоматический источник LordFilm

## Разбор архитектуры проекта

Nova состоит из основного Rust-сервера (`server/`), веб-интерфейса Svelte (`web/`),
оболочки Tauri (`desktop/`) и отдельного незавершённого Java preview (`server-java/`).
Оболочка запускает Rust-сервер внутри процесса. Java preview не обслуживает внешний поиск
и не является сервером установленного приложения.

Основные подсистемы и их отношение к просмотру:

| Подсистема | Код | Назначение |
| --- | --- | --- |
| Запуск и состояние | `server/src/lib.rs`, `host.rs` | Сервер, фоновые задачи, порты приложения и зрителей |
| Хранение | `db.rs` | SQLite, миграции, фильмы, внешние карточки, ссылки и прогресс |
| Локальная библиотека | `library/`, `meta/` | Файлы, сканирование, ffprobe, метаданные |
| Внешний каталог | `discover.rs`, `api/discover.rs` | IMDb-карточки, подборки, поиск, локализация |
| Внешние видео | `video_search.rs`, `video_sources.rs`, `api/links.rs` | Поиск, кеширование, привязка источника к карточке |
| Поток | `api/stream_link.rs`, `outbound.rs` | Поиск HLS, проксирование плейлистов и сегментов, защита локальной сети |
| Локальное воспроизведение | `stream.rs`, `hls.rs`, `copy.rs`, `api/play.rs` | Range, ffmpeg, качество, дорожки и субтитры |
| Интерфейс просмотра | `routes/ext/[id]`, `routes/watch/link/[id]`, `lib/player/Player.svelte` | Автопоиск, кнопка просмотра, собственный плеер |
| Доступ и совместный просмотр | `auth.rs`, `rooms.rs`, `api/social.rs`, `api/resume.rs` | Сессии, комнаты, общение и продолжение просмотра |
| Доставка приложения | `desktop/src-tauri/`, `access.rs`, `cloudpub.rs` | Окно хоста, обновления, внешний доступ |

Это архитектурный разбор и проверка цепочки внешнего просмотра, а не заявление о
построчном аудите всего проекта или полной проверке безопасности всех подсистем.

## Что изменено

Добавлен встроенный источник `lordfilm` для `https://sd.lordfilm5.pro/`.
При открытии карточки без локальной копии Nova проверяет только LordFilm.
Сохранённые ссылки других провайдеров не вытесняют его. Настройка `video.sites`, ключ API
и ручная вставка ссылки не нужны. Поиск сопоставляет точное нормализованное название
и год, чтобы не подменять фильм ремейком или продолжением.

После нажатия «Смотреть» обычный API ссылок сохраняет страницу фильма. Существующий
обработчик `site` находит видео на странице или во вложенном плеере и отдаёт его
через HLS-прокси собственному плееру Nova. Сохраняется обычный механизм прогресса.
В базе хранится страница фильма, а не истекающий адрес CDN.

Для сериалов автоматически ищется выбранный эпизод. Список `seasons` встроенного
плеера разбирается как JSON без исполнения JavaScript, затем выбираются точные
номера сезона и серии. Отсутствующие и заблокированные эпизоды не выдаются.
В ссылке хранится локальный фрагмент `#nova-season=1&episode=2`; он различает
эпизоды в кеше и не передаётся сайту. API проверяет соответствие фрагмента полям
сезона и серии. Существующий механизм следующей серии использует тот же поиск.

При выборе другой серии интерфейс отменяет прежний поиск и убирает старую кнопку
просмотра. Пока идёт проверка, отображается «Проверяем LordFilm…». Если результата нет
или сайт недоступен, появляется плашка «Найти на другом источнике». Только нажатие
запускает поиск в остальных провайдерах; найденное на LordFilm открывается кнопкой
«Смотреть». Следующая серия при просмотре LordFilm также ищется только на LordFilm.

Баннеры внешних карточек и главной загружаются из IMDb с отдельной отметкой
`imdbBackdrop`. TVMaze больше не запрашивается перед IMDb ради баннера. Старые
локально сохранённые изображения остаются видимыми до обновления; удалённые
баннеры запасных провайдеров не используются. При недоступности IMDb остаётся
постер, а повторная загрузка ограничена интервалом в пять минут.

Исправлено извлечение адресов вида `movie.mp4/master.m3u8`: раньше поиск мог вернуть
обрезанный `movie.mp4`. Добавлена регрессионная проверка; адрес картинки внутри
каталога с суффиксом `.mp4` также не принимается за видео.

## Границы поддержки

- Подключён указанный домен, автоматического перебора неизвестных зеркал нет.
- Поддерживаются фильмы, полнометражные мультфильмы и отдельные серии из структурированного
  плейлиста плеера `api.nextembed.ws`. Другие форматы сериальных плееров пока не разбираются.
  Источник не используется для трейлеров.
- Каталог Nova остаётся каталогом IMDb и локальной библиотеки. Полный каталог сайта
  не копируется; источник ищется автоматически при открытии фильма.
- Работа зависит от доступности сайта, его разметки и открытого потока в плеере.
  Проверка одного фильма не гарантирует доступность каждого фильма.
- Изменение относится к Rust-приложению. Java preview не получил эту функцию.

## Проверки

28 октября 2026 года проверены поиск «Дюна» (2021), разрешение страницы в HLS,
получение главного и вложенного плейлистов, получение данных видеосегмента.
Сетевые тесты помечены `ignore`, чтобы обычные проверки не зависели от чужого сайта:

```powershell
cargo test -p fsfy-server --lib lordfilm_live_movie_playlist_and_segment -- --ignored --nocapture
cargo test -p fsfy-server --test discover lordfilm_automatic_search_and_save_without_host_configuration -- --ignored --nocapture
cargo test -p fsfy-server --test discover lordfilm_series_search_save_and_stream_exact_episode -- --ignored --nocapture
```

Вторая проверка использует отдельную временную базу, пустые настройки сайтов и HTTP API
поиска/сохранения ссылки. Рабочая база хоста не используется.

Третья проверка выполняет поиск второго эпизода «Дюна: Пророчество» (2024), отклоняет
попытку сохранить его как первый, сохраняет корректную ссылку и получает через API Nova
главный плейлист, вложенный плейлист и данные сегмента. Запрос отсутствующего эпизода
возвращает пустой список. Проверки парсера отдельно покрывают отсутствующие и
заблокированные эпизоды, номера строкой и числом, недопустимые ссылки.
